# 章节质量门禁（写完一章 → 过闸 → 才准写下一章）

## 一、这个 skill 存在的理由

> **指标全绿 ≠ 写得好；写得好 ≠ 过了闸。**

`prose-scoring` 已证明：一本每项脚本指标都合格的稿子，读者读到第 16 章会发现主角死了。

所以门禁有**两条独立的轴，不许互相折算**：

| 轴 | 内容 | 谁判 | 否决权 |
|---|---|---|---|
| **A 合规轴** | 字数、段均、破折、复读、焊接、乒乓、钩子 | 脚本 | **一票否决** |
| **B 质量轴** | 连续性、文风、「没劲」、声纹、意象、节奏 | 通读 | 一票否决 |

**A 全绿而 B 不达标 = FAIL。** 不允许用「脚本都过了」放行。

---

## 二、阈值

| 场景 | 总分门槛 | 说明 |
|---|---|---|
| **续写下一章** | **≥ 92** | 日常门禁 |
| **完稿验收 / 投稿前** | **≥ 95** | 硬门槛 |

**另有两条不可折算的否决项**（无论总分多少）：
- 合规轴任意一项 FAIL → 直接 FAIL
- 主观五维中任一维**没有给出处** → 直接 FAIL（不许写「大致还行」）

---

## 三、执行流程

### 第 0 步：定位本书判据
读本书 `SKILL.md`。若其中有「本书门禁加严项」一节，**全部并入本门禁**。
本书特例（对白密集章分档、专属复现母题、专属字数区间）优先于本 skill 的通用默认值。

### 第 1 步：跑合规轴（脚本）
```bash
python3 .opencode/skills/chapter-gate/reference/gate.py --book "<书路径>" --pass 92
```
脚本输出每项的实测值、阈值、判定。**它不打总分，只判合规。**

### 第 2 步：通读给质量轴分（不可跳过）
用 `prose-scoring` 的八维表，逐章读正文，为以下五维各写一条**带出处的依据**：

| 维 | 满分 | 依据要写成什么样 |
|---|---|---|
| 2 连续性与数值链 | 20 | 「第三十二章说 247 口，全 36 章 grep 只有这一个值」 |
| 3 文风与句法 | 15 | 「句中位 11.8，长句 36/36，31 章短句过半 → 11」 |
| 4 「没劲」 | 15 | 「同构三连严格判据 0 次；物件清点 9 章轻微命中」 |
| 5 人物与声纹 | 10 | 「抽 3 章，不看书名能认出谁在说话」 |
| 6 意象系统 | 10 | 「母题 5.2 种/章，密度 11.0/千字，跨卷变奏待验」 |

**写法要求**：每维 1-3 句，必须含可核对的数字或页内位置。
无出处的分**不接受**，该项按 0 分计并标 `⚠ 无依据`。

### 第 3 步：合计与判定
```
总分 = 合规轴（维度1 全过记满分，否则 FAIL）
     + 质量轴五维得分
     + 维度 7 节奏 / 维度 8 完稿
```
判定：
- 合规 FAIL → **FAIL（不可翻案）**
- 任一维无依据 → **FAIL**
- 总分 < 门槛 → **FAIL**
- 其余 → **PASS**

### 第 4 步：失败处理（最多 3 轮）
```
第 1 轮 FAIL → 按改进清单改，改完重跑第 1-3 步
第 2 轮 FAIL → 同上，且必须换一批修法（不能重复同一处修补）
第 3 轮 FAIL → **停下，交用户**
```
交给用户时必须给出：
1. 卡在哪一项、实测值 vs 阈值
2. 已经试过哪 3 轮、每轮改了什么
3. 你判断卡住的**根因**（是字数上限不够？判据与文体冲突？还是情节本身撑不起？）
4. 2-3 个可选方案，附各自代价

**禁止**：第 4 轮自行放行；或为了过闸而放宽判据；或删掉判据里的项。

### 第 5 步：过闸后
1. 更新本书 `修改记录.md`
2. 伏笔变动回写总纲伏笔表
3. 错误登记进 `.opencode/workflow/mistakes.json`
   （复用 `chapter-finalizer` 的登记规则：新增 `times_seen:1`；复发则 `+1` 并更新 `last_seen_*`）
4. **才允许开写下一章**

## 四、合规轴判据（通用默认）

唯一字数口径：`len(re.sub(r'\s','',t))`，**含标点不含空白**。
⚠️ 禁用 `len(re.findall(r'[\u4e00-\u9fff]',t))`（纯汉字数），两口径差约 20%。

| # | 项 | 阈值 | 备注 |
|---|---|---|---|
| 1 | 字数 | 3200-3800 | 目标 3500 |
| 2 | 段均 | 按文体分档 | 见下表 |
| 3 | 破折号 | ≤ 8/章 | 不得出现在对白行内部 |
| 4 | 长句（≥45 字） | ≥ 2/章 | 叙述层承担 |
| 5 | 唯一句占比 | ≥ 0.85 | 均质度 |
| 6 | 复读 | 同一句 ≤ 2 次 | 超了算机械 |
| 7 | 焊接 | **必须为 0** | 同构块连续重复 |
| 8 | 同构三连 | **必须为 0** | 连续三个同长度同结尾的短句 |
| 9 | 章末钩子 | 必须落物证/动作 | 不得以最后一句对白收尾 |
| 10 | 场景分隔符 `——` | ≤ 3/章 | `——` 是场景切换，不算缺陷 |

**以上全部由 `reference/gate.py` 自动判定。**

### 4.1 标点粘连 —— 人工项，不做自动检测

数词紧跟数词、中间漏了标点（`三月二十四一抽`）**必须为 0**，
但**这一项不能用正则判**，必须在通读时人工看。

理由是可复现的，三者在正则层面同构：

| 类型 | 例 | 是否缺陷 |
|---|---|---|
| 真粘连 | `三月二十四一抽` | 是 |
| 正常日期 | `三月十二，四月十一` | 否 |
| AABB 叠词 | `一下一下，一格一格` | 否 |

实测曾用正则检测，对本部 36 章报出 52 处，**全部是正常日期**。
误报率 100% 的判据等于没有判据，只会被关掉。故移出自动化，列为人工必查。

### 4.2 短节拍与完整句分档

本书签名手法是拿单字应答（`"嗯。"` / `"姑娘。"`）作节拍。
一刀切会两头出错——3 次判成机械，14 次放过。故分两档：

| 项 | 阈值 | 说明 |
|---|---|---|
| 短节拍重复（去引号后 ≤4 字） | ≤ 4 次/章 | 3-4 次是风格，10 次以上是机械 |
| 完整句重复（>4 字） | ≤ 2 次/章 | 一律从严 |

**实测反例**：第033章 `"嗯。"` 曾出现 14 次 → 机械；第031章 9 次 → 机械。
分档后判定明确，无需再争论。

### 4.3 句计数必须归一化空白

判复读/唯一句时，切句后必须 `re.sub(r'\s+','',x)` 去掉内部空白。
否则多行对白段会留下 `\n` 残留在片段里，同一句话在不同段被切成不同字符串，
计数全部失真（实测偏差达 20 倍：真实 9 次被报成 203 次）。

同时**只按句末标点切，不按换行切**——按换行切会把 `"嗯。"` 切成 `"嗯`。

**段均按文体分档**（对白密集的书不能一律用 60-180）：

| 对白占比（引号内字数/总字数） | 段均合格区间 |
|---|---|
| < 18% | 60-180 |
| 18%-30% | 40-100 |
| ≥ 30% | 35-100（硬底线 35） |

## 五、门的强度

门禁的价值在于**它真的会挡住**。所以：

- **不许自我豁免**：「这本书文体特殊」不是豁免理由，要豁免必须写进本书 SKILL.md 的加严项里，**明文**列出。
- **不许降标准过关**：任何一次「今天就放宽一点」，门就永久失效。
- **不许跳轴**：合规轴过了就以为质量轴也过了。
- 每 10 章抽查一次历史章：用当时的门槛重跑，看会不会翻车。翻车说明门槛定虚了，要往上调。

## ⚠️ 批量改稿前的强制动作（2026-10 血泪追加）

### 一、改稿前必须建回滚点，且回滚点必须包含所有要改的目录

**真实事故**：某次批量修复中，一个合并脚本的索引写错，把一章 3884 字的正文砍成 1627 字。
恢复时才发现**最近几轮的手感修复从来没备份过**——全部返工。

规则：
1. 动手前复制全部要改的目录到 `修改备份/<序号>_<说明>/`
2. **说明里写清覆盖到哪一轮**（例：「13_重评前基线」）
3. 每完成一个阶段再建一个，不要只建开头一个
4. 验证回滚点里的文件能正常打开、字数合理，再开始改

### 二、批量脚本改动正文前，必须先在副本上试跑

写脚本改小说正文（合并段落、批量替换）风险极高。规则：

1. **先 `shutil.copy` 一份到 `/tmp`，在副本上跑，跑通再动真文件**
2. 脚本内每一步改完就断言字数在预期区间
3. **字数异常下跌立即中止**——几乎必然是丢了内容而不是删得干净

### 三、合并段落（并段以提升段均）的正确写法与致命陷阱

⚠️ **合并段落只能拼接，绝不能丢掉任何一段。**

```python
# 正确
parts[i:i+2] = [parts[i] + parts[i+1]]
assert all(p in ''.join(parts) for p in 原段落)   # 校验无丢失

# 错误示范（真实事故成因）：把 [前段, 后段] 替换成 [前段 + p]，
# 导致后段被丢弃。实测把 3884 字砍到 1627 字。
parts[j-1:j+1] = [parts[j-1] + p]      # ← 这里 parts[j] 消失了
```

规则：
- 合并前记录总字数，合并后必须核对，**字数下降超过删除量即为 bug**
- 用索引切片时，`parts[j-1:j+1]` 会**同时替换两个元素**，
  右值必须包含这两个元素的全部内容
- 建议改用 `parts.pop()` 取出后再 append，显式且不易错
