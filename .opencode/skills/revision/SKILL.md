# 修改润色

按三个层次由重到轻审改，产出结构化意见后再动手。

## 审稿流程

1. **先诊断，后动刀**：通读目标章节，输出问题清单（位置 + 层级 + 问题 + 建议），等用户确认范围再改。
2. 用户明确说"直接改"时可跳过确认，但结构性大改（删场景、改结局、调时间线）仍须先说明方案。

## 三层检查

### 结构层（最优先）
- 本章是否推进了至少一件事？不推进 → 建议删除或合并
- 场景顺序是否符合因果与信息揭示节奏
- 开头是否入戏太慢（前三段必须出现钩子或冲突）；结尾钩子是否有力度

### 场景层
- 节奏：连续对话超过一页 → 插动作/环境节拍；描写堆砌 → 砍一半
- 视角：是否越出了本章 POV 人物的感知
- 信息：角色"不该知道"的信息是否提前泄露

### 文字层
- 删除冗余：「地」字副词、重复形容、解释性旁白
- 对话标签多样化但不过火；连续对白超过 4 轮无动作插入需处理
- 替换 AI 腔套话（参照 `chapter-drafting` 的禁用清单）
- 朗读测试：拗口的长句拆短

## 输出格式

```
【结构】第N段：问题 → 建议
【场景】第M段：问题 → 建议
【文字】原句 → 改句（理由）
```

## 红线

- 不擅自改变情节走向和人物性格——那是用户的决定。
- 改完在 `章节大纲/第X部/逐章卡片.md` 将章节状态标为「已修改」，涉及伏笔变动同步 `章节大纲/总纲.md` 伏笔总表。
