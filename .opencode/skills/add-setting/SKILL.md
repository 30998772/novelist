# 补充设定

把用户提供的任何新素材、新设定规范地并入项目文件，保持全书一致性。

## 素材去向表

| 素材类型 | 写入位置 |
|----------|----------|
| 人生经历、事件片段 | `outline/storyline/storyline.md` 对应阶段小节下追加 |
| 人物信息（性格、关系、外貌） | `outline/character/character.md` 新增或更新对应档案 |
| 情节走向、章节安排调整 | `outline/polt/polt.md` 的章节卡片 |
| 年代、地点、背景等世界设定 | `outline/polt/polt.md` 的「写作约定」区块 |
| 新伏笔 | `polt.md` 伏笔登记表，F-编号顺延 |

## 工作流程

1. **复述确认**：先把用户口述的素材整理成条目清单复述一遍；明确的事实直接入库，含糊之处单独列出。
2. **冲突预检**（必做）：新设定落盘前，用 Grep 在 `storyline.md`、`character.md`、`polt.md` 及已发布章节中检索相关关键词：
   - 与既有设定一致 → 直接写入；
   - 与正文或档案矛盾 → 停下，报告差异点，给出「改设定」或「改正文」两个选项，由用户决定后再动笔。
3. **落盘**：按去向表写入，只追加不删改用户的原始表述；确需修订旧条目时，保留原句并在其后以批注说明修订原因。
4. **联动更新**：
   - 出现新人物 → 同步建档案（套用 `character-design` 模板）；
   - 埋下新伏笔 → 登记表加行，注明预计回收位置；
   - 影响已完成章节 → 提示调用 `continuity-check` 复核；
   - 影响后续细纲 → 更新对应章节卡片并标注「因新设定修订」。

## 标注规范

每条新设定必须带状态标记：

- 【硬设定】不可违反，正文必须遵守（如年代、家庭成员、关键事实）
- 【软设定】氛围类，可灵活处理
- 【补白】由现有素材合理推断而来，待用户确认
- 【待确认】信息不全，列明缺口问题

## 红线

- 严禁覆盖或删除用户原始素材条目——那是唯一事实来源。
- 严禁在未做冲突预检时直接写入。
- 入库完成后必须回执：列出本次改动的文件、新增条目数、新伏笔编号、【待确认】清单。
